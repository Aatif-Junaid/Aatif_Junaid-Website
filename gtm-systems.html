How I design GTM systems that keep humans in control.

The system should gather signal, draft the next move, and leave judgment with the operator.

The pattern

GTM work fails when signal has nowhere to go

Most go-to-market teams do not lose because they lack tools. They lose because customer signal sits in too many places: LinkedIn threads, call notes, demo forms, CRM fields, product analytics, and follow-up tasks. The handoff becomes memory. Memory does not scale.

The systems I like are small enough to trust and explicit enough to audit. They do not replace the operator. They remove the repetitive work around the operator: capture the signal, structure it, suggest the next step, and make the human approval point obvious.

Workflow

A simple AI-assisted lifecycle loop

I built a GTM lifecycle engine in n8n that turns public market signals into cited, human-reviewed content drafts. Three EIA market signals enter through an RSS feed, pass a source gate, get drafted by Anthropic against a fixed schema, and stop in an approval queue. A scheduled second track picks up only the rows I mark approved and records LinkedIn-ready, email-ready, and CRM-ready outcomes to a lifecycle log.

Lifecycle log

Every run writes a CRM-shaped event: source, verification status, channel, stage, and outcome. HubSpot reads that structure directly.

The LinkedIn and HubSpot nodes sit on the canvas and the payloads are built for them. I left those two credentials off on purpose: a demo that runs on a schedule has no business holding publish rights to a live feed or write access to a real CRM. Connecting them is a credential step, not a redesign.

The build

Two tracks, one sheet, one approval column

The whole engine is one n8n workflow with two triggers. The intake track runs on a manual trigger so I can start a demo on demand. The distribution track runs on a schedule, so once I approve a row in the sheet, nothing else needs a hand. State lives in one Google Sheet with three tabs. The model never writes to a channel. It writes a row.

Track 1: intake to approval queue

  1. Read Market SourceRSS Read against the EIA Today in Energy feed. The run starts from a public, named source, not typed-in text.
  2. Limit Demo IntakeLimit node, set to 3. Enough to prove the loop, small enough to watch in one recording.
  3. Normalize GTM SignalMaps RSS fields into the eleven-column source schema: link becomes source_url, title becomes topic, isoDate is cut to a date, and every row is stamped with source_quality, source_verified, and status New. Every node after this relies on those names staying stable.
  4. Deduplicate SignalsRemove Duplicates keyed on the source_url column. One signal cannot draft twice in a run.
  5. Require Named SourceFilter. A row moves forward only if source_url, summary, company, and source_quality exist and status is New. Rows that fail go to Log Suppressed Signal, which writes a source_rejected event to the lifecycle log. Nothing is dropped silently.
  6. Save Source EvidenceGoogle Sheets append-or-update on source_signals, matched on source_url. The evidence row exists before the model runs.
  7. AI ModelAn Anthropic chat model with a structured output parser. The prompt passes only the normalized fields, forbids invented facts, requires the named source in the body and the URL at the end, and sets approval_status to Pending. The parser forces a sixteen-field JSON shape.
  8. Draft From Cited InputsFlattens the parsed output into one row per draft. The sheet receives draft_id, draft_subject, draft_body, gtm_takeaway, why_it_matters, source_url, and the approval fields, not a nested JSON blob.
  9. Write To Approval QueueAppend-or-update on approval_queue, matched on draft_id. The draft stops here and waits for me.

Track 2: approval to lifecycle log

  1. Scheduled Approval CheckSchedule trigger. The only other entry point in the workflow.
  2. Read Approved DraftsReads approval_queue for rows where approval_status is Approved and processed_status is blank.
  3. Approval GateFilter on two Boolean checks: approval_status equals approved, and processed_status is empty. Explicit approval, and no second pass on the same row.
  4. WaitA short pause between the gate and the channel steps, so the run reads clearly on the canvas.
  5. Send Approved EmailGmail send. Subject is draft_subject, body is draft_body, taken from the approved draft payload directly. Record Email Send Ready then writes the email outcome to the log.
  6. Record LinkedIn Draft ReadyWrites the LinkedIn-ready event to the lifecycle log: channel LinkedIn, journey_stage approved_for_distribution, outcome ready for manual publish.
  7. HubSpot CRM Log ReadyShapes the same event as a CRM lifecycle record. The HubSpot node sits on the canvas and is intentionally left unauthenticated.

Where the data lives

  1. source_signalsThe audit trail

    Eleven columns: source_url, source_name, published_date, company, topic, signal_type, summary, source_quality, status, is_demo_data, source_verified. Written before any draft exists.

  2. approval_queueThe human control point

    Sixteen columns, including draft_subject, draft_body, gtm_takeaway, why_it_matters, confidence, approval_status, reviewer_note, approved_at, processed_status, and processed_at. A row is born Pending. I read it, set approval_status to Approved, add a note and a date. The schedule does the rest.

  3. lifecycle_logThe event trail

    Every gate decision and every distribution outcome lands here as one row: event_time, run_id, channel, action_taken, journey_stage, analytics_event, outcome, plus the source fields carried through. This is the CRM-shaped record.

How it authenticates

Credentials are split by vendor and stored once in n8n. Google Sheets authenticates through an OAuth2 web-application client in Google Cloud, with the Sheets API enabled and the Drive API enabled for file browsing. The client's JavaScript origin and redirect URI are registered against the n8n instance, and the Google account is listed as a test user while the OAuth app sits in testing. Gmail authenticates through Google OAuth2 as well. Anthropic is a separate API-key credential that feeds the chat model subnode. LinkedIn and HubSpot are intentionally left unauthenticated. That is the point: a scheduled demo should not hold publish rights or CRM write access.

Controls

The system has to earn trust before it earns scale

01Source gateFour required fields and a status check before anything drafts. Rejections are logged as source_rejected, not dropped.
02Dedupe on the keyRemove Duplicates keyed on the literal source_url column, not the evaluated URL. One signal, one draft.
03Two-check approvalThe gate needs approval_status equal to approved and processed_status blank. No unapproved rows, no double runs.
04Evidence firstThe source row is saved before the model is called. Every draft traces back to a stored row.
Why it matters

This is how a lean GTM team acts larger than it is

The point is not automation for its own sake. The point is better judgment under more load. When the system handles capture, routing, drafts, reminders, and logging, the human has more time for the work that cannot be templated: positioning, buyer understanding, objection handling, and deciding which opportunities are real.
