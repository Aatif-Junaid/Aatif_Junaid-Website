The pattern

GTM work fails when signal has nowhere to go

Most go-to-market teams do not lose because they lack tools. They lose because customer signal sits in too many places: LinkedIn threads, call notes, demo forms, CRM fields, product analytics, and follow-up tasks. The handoff becomes memory. Memory does not scale.

The systems I like are small enough to trust and explicit enough to audit. They do not replace the operator. They remove the repetitive work around the operator: capture the signal, structure it, suggest the next step, and make the human approval point obvious.

Workflow

The GTM lifecycle engine

One n8n workflow, two scheduled tracks, one Google Sheet in the middle. Public market signals enter through an RSS feed, pass a source gate, get drafted by Claude against a fixed schema, and stop in an approval queue. The second track picks up only the rows I mark Approved, sends the draft to my own inbox, prepares the LinkedIn post, and records every outcome in a lifecycle log. The model never writes to a channel. It writes a row.

The build

Two tracks, one sheet, one approval column

The whole engine is one n8n workflow with two schedule triggers, both set to every minute. The workflow stays inactive between demos, so every run is one I start on purpose. State lives in one Google Sheet with three tabs. The nodes below are the ones in the export, in the order they run.

Track 1: intake to approval queue

  1. Schedule TriggerRun GTM Engine Demo

    Fires every minute while the workflow is active.

  2. RSS ReadRead Market Source

    EIA Today in Energy. A public, named source, not typed-in text.

  3. Limit · 3Limit Demo Intake

    Enough to prove the loop, small enough to watch in one recording.

  4. SetNormalize GTM Signal

    Link becomes source_url, title becomes topic, the date is cut to YYYY-MM-DD, and every row is stamped source_quality High, source_verified Yes, status New.

  5. Remove DuplicatesDeduplicate Signals

    Keyed on source_url. One signal cannot draft twice in a run.

  6. IfRequire Named Source

    source_url, summary, company, and source_quality must exist, status must be New, and source_verified must be Yes. The false branch runs Log Suppressed Signal, which writes a source_rejected row to the log. Nothing is dropped silently.

  7. Google SheetsSave Source Evidence

    Append or update on source_signals, matched on source_url. The evidence row exists before the model runs.

  8. LLM chainAI Model

    Claude Opus 5 through the Anthropic chat model subnode. The prompt passes only the normalized fields, forbids invented facts, and requires a citation with the source name and URL. A structured output parser forces a 16-field JSON shape.

  9. CodeDraft From Cited Inputs

    Flattens the parsed output into one row per draft, with channel LinkedIn, confidence High, and approval_status Pending as the defaults.

  10. Google SheetsWrite To Approval Queue

    Append or update on approval_queue, matched on draft_id. The draft stops here and waits for me.

Track 2: approval to lifecycle log

  1. Schedule TriggerScheduled Approval Check

    The only other entry point in the workflow. Every minute.

  2. Google SheetsRead Approved Drafts

    Reads approval_queue for rows where approval_status is Approved and processed_status is blank.

  3. FilterApproval Gate

    Two checks, both required: approval_status equals approved, processed_status is empty. Explicit approval, and no second pass on the same row.

  4. Wait · 2 sWait

    A short pause, then the run fans out to two channels at once.

  5. GmailSend Approved Email

    Subject is draft_subject, body is draft_body, sent to my own inbox. A second 2-second Wait follows, then Record Email Send Ready writes the outcome to the log.

  6. LinkedInLinkedIn Draft Ready

    Wired in, aimed at a placeholder organization. Record LinkedIn Draft Ready logs channel LinkedIn, stage approved_for_distribution, outcome ready for manual publish.

  7. HubSpotHubSpot CRM Log Ready

    An engagement node shaped to log the email as a CRM activity. No credential, no connection, by design.

How it authenticates

Credentials are split by vendor and stored once in n8n. The instance is https://n8n.aatifmulla.me. Its MCP server at /mcp-server/http is a separate surface, not the OAuth callback.

  • Google SheetsOAuth2 web client

    A Google Cloud client with the Sheets and Drive APIs enabled. Redirect URI https://n8n.aatifmulla.me/rest/oauth2-credential/callback. My account is a test user while the app sits in testing. Six nodes share it.

  • GmailGoogle OAuth2, send only

    One node uses it, and it sends to my own address. Nothing goes to a prospect.

  • AnthropicAPI key

    Feeds the chat model subnode and nothing else.

  • LinkedIn and HubSpotNo live rights

    LinkedIn is aimed at a placeholder organization, so nothing publishes. HubSpot holds no credential and no connection. A scheduled demo should not have publish or CRM write access.

Controls

The system has to earn trust before it earns scale

01 · Require Named SourceSource gateAn If node. Four fields must exist, status must be New, source_verified must be Yes. Anything else is written to the log as source_rejected, never dropped silently.
02 · Deduplicate SignalsOne signal, one draftRemove Duplicates keyed on source_url, before the gate. The same link cannot draft twice in a run.
03 · Approval GateTwo-check approvalapproval_status must equal Approved and processed_status must be blank. No unapproved rows, no second run on the same row.
04 · Save Source EvidenceEvidence before the modelThe source row is written to source_signals before the AI node runs. Every draft traces back to a stored row.
Why it matters

This is how a lean GTM team acts larger than it is

The point is better judgment under more load. When the system handles capture, routing, drafts, and logging, the operator keeps the work that cannot be templated: positioning, buyer understanding, objection handling, and deciding which opportunities are real.
