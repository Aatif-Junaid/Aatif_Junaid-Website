The pattern

GTM work fails when signal has nowhere to go

  • Signal lives in six places. LinkedIn threads, call notes, demo forms, CRM fields, product analytics, follow-up tasks.
  • The handoff between them is memory. Memory does not scale past one operator.
  • A good system does three things. Capture the signal, structure it, suggest the next step.
  • It keeps one thing for the human. The approval.
  • It stays small enough to trust and explicit enough to audit.
Workflow

The GTM lifecycle engine

  • One n8n workflow. Two scheduled tracks, one Google Sheet between them.
  • In: public market signals from an RSS feed, 3 per run.
  • Gate: a named source, or the row is logged as rejected.
  • Draft: Claude writes against a fixed 16-field schema, citation included.
  • Stop: every draft waits in the approval queue as Pending.
  • Out, only after I approve: an email, a LinkedIn-ready post, and one lifecycle log row each.
  • The model never writes to a channel. It writes a row.

The build

Two tracks, one sheet, one approval column

  • One workflow, two schedule triggers, both set to every 5 minutes.
  • Inactive between demos, so every run is one I start on purpose.
  • The nodes below are the ones in the export, in the order they run.

Track 1: intake to approval queue

  1. Schedule TriggerRun GTM Engine Demo

    Fires every 5 minutes while the workflow is active.

  2. RSS ReadRead Market Source

    EIA Today in Energy. A public, named source, not typed-in text.

  3. Limit · 3Limit Demo Intake

    Enough to prove the loop, small enough to watch in one recording.

  4. SetNormalize GTM Signal

    Link becomes source_url, title becomes topic, the date is cut to YYYY-MM-DD, and every row is stamped source_quality High, source_verified Yes, status New.

  5. Remove DuplicatesDeduplicate Signals

    Keyed on source_url. One signal cannot draft twice in a run.

  6. IfRequire Named Source

    source_url, summary, company, and source_quality must exist, status must be New, and source_verified must be Yes. The false branch runs Log Suppressed Signal, which writes a source_rejected row to the log. Nothing is dropped silently.

  7. Google SheetsSave Source Evidence

    Append or update on source_signals, matched on source_url. The evidence row exists before the model runs.

  8. LLM chainAI Model

    Claude Opus 5 through the Anthropic chat model subnode. The prompt passes only the normalized fields, forbids invented facts, and requires a citation with the source name and URL. A structured output parser forces a 16-field JSON shape.

  9. CodeDraft From Cited Inputs

    Flattens the parsed output into one row per draft, with channel LinkedIn, confidence High, and approval_status Pending as the defaults.

  10. Google SheetsWrite To Approval Queue

    Append or update on approval_queue, matched on draft_id. The draft stops here and waits for me.

Track 2: approval to activation and log

  1. Schedule TriggerScheduled Approval Check

    The only other entry point in the workflow. Every 5 minutes.

  2. Google SheetsRead Approved Drafts

    Reads approval_queue for rows where approval_status is Approved and processed_status is blank.

  3. FilterApproval Gate

    Two checks, both required: approval_status equals approved, processed_status is empty. Explicit approval, and no second pass on the same row.

  4. Wait · configurableCustom wait

    A hold I set before anything goes out. Seconds in the demo; a review window in a real motion. Then the run fans out.

  5. Gmail · activationSend Approved Email

    Subject is draft_subject, body is draft_body, sent to my own inbox in the demo. A second hold follows, then Record Email Send Ready writes the outcome to the log.

  6. LinkedIn · activationLinkedIn Draft Ready

    Posts as an organization through the LinkedIn node. Record LinkedIn Draft Ready logs channel LinkedIn, stage approved_for_distribution, outcome ready for manual publish.

  7. HubSpot · activationHubSpot CRM Log Ready

    An engagement node that logs the email as a CRM activity against the contact.

How it authenticates

Credentials are split by vendor and stored once in n8n, on the self-hosted instance at n8n.aatifmulla.me.

  • Google SheetsOAuth2 web client

    A Google Cloud client with the Sheets and Drive APIs enabled and the n8n callback registered. Six nodes share it.

  • GmailGoogle OAuth2, send scope

    One node uses it. In the demo it sends to my own inbox.

  • AnthropicAPI key

    Feeds the chat model subnode and nothing else.

  • LinkedInOAuth2, organization posting

    The LinkedIn node authenticates with a LinkedIn OAuth2 credential and posts as an organization.

  • HubSpotPrivate app token or OAuth2

    The HubSpot node authenticates with either and writes the engagement to the CRM.

Why it matters

This is how a lean GTM team acts larger than it is

The point is better judgment under more load. When the system handles capture, routing, drafts, and logging, the operator keeps the work that cannot be templated: positioning, buyer understanding, objection handling, and deciding which opportunities are real.
